# 残片系统与通讯终端 v0.1

> 本文记录 ECHO 残片构筑与通讯终端的已确认设计，以及当前 PR 的首版实现边界。数值库仍属于第一版测试数值，不代表最终平衡封版。

## 1. 残片系统

### 1.1 核心规则

- 残片由独立模块实例组成，不使用随机副词条刷取、洗练、重铸或隐藏品质。
- 每名角色拥有 6 个模块槽位和 12 点总容量；小型/中型/大型分别消耗 1/2/3 点。
- 单槽最多安装一个模块；同类模块可重复装备，但必须是不同实例。
- 单个实例同一时间只能装备给一名角色。
- 非战斗状态可自由安装、卸下和转移；战斗开始时将当前配置应用到角色，战斗中不开放改装。
- 不要求填满槽位；无收益模块不应为了占槽而安装。

### 1.2 模块生成

- 小型：七种属性中等概率随机一种，单属性固定数值。
- 中型：七种属性中均匀随机两种不同属性，共 21 种组合，两条属性地位相同。
- 大型：玩家先选固定主词条，再从其余六种属性中等概率随机一个副词条；主副词条生成后永久固定。
- 不按角色或构筑方向过滤随机结果；低价值组合允许自然出现。

### 1.3 第一版测试数值库

| 属性 | 小型 | 中型 | 大型主词条 | 大型副词条 |
|---|---:|---:|---:|---:|
| 攻击力 | +4% | +3% | +7% | +1% |
| 生命值 | +5% | +4% | +8% | +1% |
| 防御力 | +3% | +2% | +5% | +1% |
| 暴击率 | +1.5个百分点 | +1个百分点 | +2.5个百分点 | +0.5个百分点 |
| 暴击伤害 | +6个百分点 | +4个百分点 | +10个百分点 | +2个百分点 |
| 魔法抗性 | +3% | +2% | +5% | +1% |
| 治疗效率 | +5% | +3% | +8% | +1% |

- 所有角色基础暴击率为 0%，基础暴击伤害为 150%。
- 暴击率与暴击伤害独立成长；暴击率按百分点增加。
- 治疗效率只作用于实际治疗，不作用于普通恢复道具或明确不属于治疗的固定恢复。

### 1.4 智能构筑

四个方向：攻击爆发、坚韧防御、治疗辅助、均衡构筑。

- 从当前角色已装备模块和未装备库存中计算；排除其他角色正在使用的实例。
- 遵守 6 槽与 12 容量限制，可留空。
- 每次只给出一套当前条件下的最佳可行配置；模块不足时仍给出最佳可行解。
- 评分相同时优先保留当前装备，再减少不必要变更，最后按稳定实例 ID 决定顺序。
- 当前配置已最优时明确提示。
- 无实际治疗能力的角色不提供治疗辅助方向。

首版使用基于角色基础属性与技能倍率的加权背包优化；方向权重属于首版可调测试参数，需结合后续角色技能与实战数据继续校准，不视为最终平衡公式。

### 1.5 角色预览与残片中心

- 工坊大厅提供独立角色总览、残片中心入口。
- 角色总览进入角色详细预览，展示基础/最终属性、技能倍率、命中段数、范围、形状与技能描述。
- 角色预览可跳转残片中心，并自动选中当前角色。
- 残片中心管理库存、六个装备槽、容量、安装/卸下/转移和智能构筑。
- 角色战斗属性在遭遇开始时读取已装备模块；暴击率、暴击伤害进入统一伤害管线。

## 2. 通讯终端

### 2.1 邮件与分类

- 工坊大厅常驻入口，分别显示未读数量与待领取奖励数量。
- 分类：收件箱、公告、奖励、归档。
- 邮件支持已读、归档、附件领取与一键领取。
- 普通邮件、公告、奖励邮件、公告奖励邮件采用统一数据模型。
- 邮件有效期与保留期分离；永久邮件以 expires_at = 0 表示。
- 未领取且仍有效的奖励附件阻止普通删除；归档不等于删除。

### 2.2 账号与存档边界

- 邮件归属于本地账号资料，不属于单个角色。
- 奖励领取记录绑定邮件附件和目标进度存档；成功领取后不能重复发放。
- 当前原型只有一个本地进度槽，只有 AtelierStash 存档存在且通过读取校验时才视为有效；领取时自动选择 default。缺失或损坏时拒绝领取，不创建替代存档。服务接口以槽位集合建模，未来出现多个有效存档时再要求玩家选择。
- 当前版本是本地邮件数据层，不连接正式账号服务器，不代表真实官方服务器发信。
- 官方发信后台、跨设备同步、推送通知和在线账号服务不属于本 PR 的实现范围。

### 2.3 奖励交易

- 每个附件独立领取；单个附件失败不应把其余附件标记为已领取。
- 随机模块首次成功生成时保存完整属性、实例 ID 和附件领取记录。
- 邮箱状态与模块库存通过本地写前日志交易恢复，避免崩溃后出现已领取但未到账或重复到账。
- 随机结果一经保存，重新登录、读档、重开邮件或重试均不得重新生成。
- 账号级附件领取账本独立于邮件列表；删除已领取邮件不会删除领取记录，也不能通过重新投递同一邮件 ID 再次领取。

## 4. 首版实现边界与后续工作

当前 PR 目标是完成单机本地可用闭环：角色预览、模块库存与装配、战斗属性接入、构筑推荐、本地通讯终端、永久测试奖励邮件和领取防重复。

当前只有一个有效本地进度槽；多存档选择、在线账号邮箱、服务端交易、官方发信后台和跨设备同步保留接口/数据边界，不在本次实现中宣称已完成。治疗效率的数据字段与角色构筑识别已预留，现有可玩角色尚无常规治疗技能，因此治疗辅助方向不会对其开放。
