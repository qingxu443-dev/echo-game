## 1. 目的

敌方 AI 与预告系统让敌方威胁在结算之前就可被理解，并保证展示的威胁与实际执行的动作一致。

核心设计承诺：

> 敌人的威胁必须可被理解，玩家的选择必须有意义，规则必须值得信任。

对普通敌人而言，预告必须准确表达最终的目标、区域、伤害与特殊效果。特殊敌人只有在变更对玩家而言事前已明确披露时才可更改意图。会变更预告的特殊敌人不在 Prototype 0.1 范围内，除非另行批准。

## 2. Prototype 0.1 范围

包含：
- 三种普通敌人
- 从每个敌人的合法动作集合中进行确定性意图选择
- 玩家回合开始时生成预告
- 可见的敌方执行顺序
- 来源敌人阵亡时取消其预告
- 通过渲染预告所用的同一份权威意图/动作定义执行
- 失效意图的基础处理与记录（受第 13 节决策约束）

排除：
- Boss 阶段与特殊意图变更
- 复杂学习型/自适应 AI
- 程序化敌人特性
- 大型敌人词缀池
- 隐藏的预告变更
- 故意欺骗玩家的敌人

## 3. 系统职责

### EnemyDecisionSystem（敌方决策系统）

负责：
- 读取敌人当前的权威状态。
- 枚举敌人被允许执行的动作。
- 评估合法的目标、格子与区域。
- 按已批准的优先级与并列规则选择一条意图。
- 产出意图记录，不直接改动战场。

不得：
- 消耗玩家 AP。
- 在规划期间改动玩家或伙伴状态。
- 自行绘制 UI 预告形状。
- 在意图生成期间结算伤害。

### TelegraphSystem（预告系统）

负责：
- 接收已选定的意图记录。
- 创建并维护预告表现。
- 向 UI 暴露确切的目标、区域、效果摘要、来源敌人与执行顺序。
- 来源敌人阵亡时立即取消预告。
- 仅通过显式批准的规则更新或使意图失效。

不得从动作记录之外独立决定不同的目标、区域或伤害值。

### EnemyActionResolver（敌方动作结算器）

负责：
- 在敌方阶段执行意图的动作定义。
- 通过共享的战斗/动作结算管线应用效果。
- 上报实际结算结果。
- 恰好一次地将意图标记为已结算或已取消。

不得在执行时重跑一次无约束的 AI 选择并悄悄替换已展示的意图。

### Battle UI（战斗界面）

负责呈现权威数据：
- 敌人身份与当前状态
- 预告形状与受影响格子
- 适用时的目标身份
- 已知的预估伤害与特殊效果
- 敌方执行顺序
- 多个敌人预告之间清晰的视觉区分

UI 是只读表现层，不得独立计算目标或结果。

## 4. 意图数据模型（建议）

意图应表示为稳定的运行时记录。字段名为临时方案。

**已确认的目标原则：** 采用混合目标模型。目标模式由每个动作的设计选定，而不是把所有敌方动作强行套进同一种锁定类型。一个动作可锁定角色、格子或区域。所选模式及其后果必须在预告中清晰可见。

**已确认的目标移动与击败行为：** 角色锁定的动作持续追踪其指定角色；格子锁定的动作在最初标记的格子结算；区域锁定的动作在最初标记的区域结算。若角色锁定的动作所指定目标在执行前被击败，该动作取消，不重新选择其他角色，也不退还或补偿玩家 AP。该敌人的行动槽位在本阶段视为已结算。

| 字段 | 用途 |
|---|---|
| intent_id | 战斗局内唯一标识 |
| source_actor_id | 拥有该意图的敌人 |
| action_definition_id | 待执行的共享动作定义 |
| target_mode | 已确认混合模型：角色锁定 / 格子锁定 / 区域锁定，按动作选定 |
| target_actor_id | 目标角色（如适用） |
| target_cell | 目标格子（如适用） |
| affected_cells | 已解析的区域预览 |
| damage_preview | 预期伤害或明确定义的区间 |
| effect_preview | 状态、位移、召唤或其他效果摘要 |
| execution_order | 可见的顺序编号 |
| creation_turn | 创建该意图的玩家回合 |
| state | 建议：active（活动）、resolved（已结算）、canceled（已取消）、invalidated（已失效） |
| disclosure | 执行前必须告知玩家的任何特殊规则 |

意图记录仅为运行时战斗数据，不得为局内恢复而持久化。

## 5. 意图生成生命周期

每个玩家回合开始时：

1. 按已批准的回合开始时序开启新的玩家回合。
2. 读取当前位置、生命、状态、地形与单位可用性。
3. 为每个存活的合格敌人枚举可用动作。
4. 过滤不满足条件的动作。
5. 为每个候选动作枚举合法目标或目标格。
6. 用确定性的、已文档化的选择规则选定一条意图。
7. 从选定的动作定义解析预告几何与预览值。
8. 分配可见的执行顺序。
9. 向 UI 发布完整意图列表。
10. 开启玩家动作窗口。

AP 重置、状态更新、伙伴可用性重置与预告生成之间的确切关系，仍由「战斗事件与结算时序」文档的决策过程管辖。

处于被击败、按已批准规则被禁止行动或其他不合格状态的敌人不得生成攻击预告。「被禁止」的确切定义仍待与状态/控制规则一同定稿。

## 6. 选择策略

原型 AI 应当简单、可读、可测，而不是精巧。

规划基线：
- 每个普通敌人拥有一套小型的、手工编排的动作集。
- 候选动作在选定前先按合法性过滤。
- 优先级规则显式且稳定。
- 两个候选优先级相同时，用已文档化的并列规则选定其一。
- 若未来引入随机性，不得导致预告与执行相互偏离。任何随机选择必须在意图生成期间做出并捕获进意图记录。

待决：
- 普通敌人采用固定优先级、加权选择、距离规则，还是小型确定性状态机。
- 并列按固定动作 ID 顺序、目标距离，还是存储的随机选择来裁决。
- 无合法攻击的敌人是待机、防御、转移，还是使用回退动作。

原型评估建议（当时未获批）：使用手工编排的优先级规则与确定性并列裁决；避免执行时的全新随机选择。

## 7. 预告表现要求

每个普通敌人的预告在适用时应传达：

- 哪个敌人将行动。
- 哪个角色被锁定，或哪个格子/区域受威胁。
- 确切受威胁的格子。
- 预期伤害，或在战斗公式无法给出确切值时明确标注的伤害区间。
- 特殊效果，如击退、拉拽、眩晕、破甲或地形变化。
- 该敌人在执行顺序中的位置。

表现要求：
- 多个敌人不得仅靠颜色区分。
- 颜色之外还要使用形状、描边、图案、图标和/或来源标记。
- 预告在横屏手机屏幕上必须可读。
- 提供逐个检视重叠威胁的方式。
- 不过度遮挡网格或关键单位轮廓。
- 长按或其他显式检视交互可以揭示细节；具体手势行为属于 UI 规范。

## 8. 意图稳定性与失效

预告在玩家回合开始时生成，并在玩家动作窗口期间保持稳定，除非已确认规则更改或取消它。

以下情形需要显式策略决策：

### 来源敌人阵亡

已确认：立即取消其预告，不得在后续执行。

### 目标移动

待决：动作是继续锁定原角色、原格子，还是重新评估目标？预告必须传达所选模型。

### 目标离开受威胁区域

待决：动作在原区域结算、失败，还是使用已文档化的回退？

### 目标在执行前被击败

待决：动作是取消、重选，还是在原位置结算。不得悄悄重选目标。

### 敌人被控制或打断

待决：定义成功与失败效果、时长，以及预告被取消、延迟、削弱还是保留。

### 先执行的敌方动作改变棋盘

待决：当前一个敌人击退单位、封锁格子、击败目标或使后续敌人意图失效时的处理。

### 地形变化

待决：预告几何在地形变化后锁定还是重算。任何变化必须在执行前披露。

实现绝不得用实质不同的动作悄悄替换已预告的动作。

*（现状注：上述各「待决」项已按 `docs/engineering/decisions/DECISIONS_AND_OPEN_QUESTIONS.md` 的已确认规则收口：混合锁定模型、失效即取消、绝不重选、地形不扩大范围不换目标。）*

## 9. 执行生命周期

敌方阶段开始时：

1. 关闭玩家输入。
2. 读取已发布的执行顺序。
3. 按该顺序逐条访问意图。
4. 检查其来源敌人是否仍存活且合格。
5. 应用已批准的失效策略。
6. 用预告所用的同一份动作定义与捕获的意图参数结算动作。
7. 记录实际目标、受影响格子、伤害与效果。
8. 恰好一次地将意图标记为已结算或已取消。
9. 除非战斗已进入终止状态，继续下一条意图。

执行结算器不得执行与已展示预告相矛盾的无约束目标搜索。

## 10. 三敌人内容规范模板

Prototype 0.1 的每种敌人必须记录：

- 名称与战场角色
- 基础生命与移动（获批后）
- 动作定义与 AP/回合时机（如相关）
- 目标模式
- 射程与区域几何
- 伤害/效果预览
- 选择优先级与并列裁决
- 预告外观与图标
- 玩家反制选项
- 失效目标行为
- 测试用例

**已确认的 Prototype 0.1 敌方角色名单（三种普通敌人）：**
1. **近战先锋：** 制造近距离压迫，考验间距控制、移动与防御应对。其已批准的行为方向为混合式：平时持续追击施加近战压力，满足条件时使用蓄力重击。详细行为与初始调参值见第 10.1 节；数值平衡仍以实机测试为准。
2. **远程神射手：** 制造远程威胁，考验站位、射线与远程预告应对。
3. **区域术士（区域控制者，area controller）：** 制造区域威胁，考验区域拒止、转移与时机决策。

现阶段仅这三种战场角色已获确认。名称、视觉设计、基础数值、确切动作、目标模式分配、优先级与具体数字均待定稿；角色描述不构成对任何具体攻击的批准。

## 10.1 近战先锋 — Prototype 0.1 行为规范

> 状态：授权委托下由项目维护者选定的实现基线。数值平衡仍以实机测试为准。

### 角色与教学目标

近战先锋是入门压迫型敌人。它教玩家读距离、保留退路，并区分「追踪角色的攻击」与「锁定固定格的攻击」。其行为刻意保持确定性，不含任何隐藏目标变更。

### 运行画像（初始调参值）

| 属性 | 初始值 | 备注 |
|---|---:|---|
| 生命 | 6（现值 3200） | 调参基线，不是最终平衡 |
| 移动 | 最多 2 个正交格 | 每敌方阶段一次移动动作 |
| 普通攻击伤害 | 1（现按倍率结算） | 角色锁定 |
| 蓄力重击伤害 | 2（现按倍率结算） | 格子锁定 |
| 普通攻击射程 | 曼哈顿距离 1 | 仅正交相邻格 |
| 蓄力重击射程 | 曼哈顿距离 2 | 目标格须有无遮挡的正交直线可达 |
| 蓄力重击作用范围 | 单个标记格 | 无溅射伤害 |

> **数值现状（2026-11-25）**：先锋现行属性为生命 3200、攻击 1400、防御 700、法抗 350（`data/enemies/vanguard.tres`）；近战攻击为 0.8× 物理、蓄力重击为 1.5× 物理（`intent_planner.gd`），最终伤害按递减收益公式经目标防御减免。上表「初始值」列保留为决策记录。

### 动作 A — 追击

- 两种攻击均不合法时使用。
- 选择曼哈顿距离最短的存活玩家方单位；并列按稳定角色 ID 裁决。
- 按确定性邻格顺序（上、右、下、左）寻找通往该单位的最短合法路径。
- 沿该路径最多移动两格，在占用或阻挡格之前停下。
- 若任何合法步都无法缩短距离，则生成显式 `wait`（待机）意图。待机占据该敌人可见的执行顺序槽位，结算时不移动、不造成伤害。
- 追击不是攻击，不产生伤害预告。但敌人的移动意图与终点仍应可在执行顺序面板中检视。
- 移动绝不穿过对角边、墙体、障碍或占用格。

### 动作 B — 普通近战攻击

- 存活玩家方单位处于正交相邻时合法。
- 目标模式：**角色锁定**。
- 选择当前生命比例最低的相邻目标；并列按稳定角色 ID 裁决。
- 预告：展示来源敌人、具名目标与目标角色当前格。
- 执行时，若该目标已移动则继续追踪同一角色。
- 若该目标在执行前被击败，取消动作；不重选目标。
- 初始伤害：1（现按 0.8× 物理倍率结算）。

### 动作 C — 蓄力重击

- 存活玩家方单位恰在正交直线上距离 2 格且直线无遮挡时合法。
- 目标模式：**格子锁定**。
- 按当前生命比例最低、其次稳定角色 ID 选择合格目标。
- 预告单个原始目标格，带独特的蓄力标记与明确的伤害预览。
- 即使该单位移开，攻击仍在原始格结算。它不追踪角色，也不扩展到相邻格。
- 若原始格被阻挡或按共享动作校验规则不再合法，取消重击并记录原因。
- 初始伤害：2（现按 1.5× 物理倍率结算）。
- Prototype 0.1 中不含位移、眩晕、破甲或地形效果。

### 选择优先级与阶段行为

玩家回合开始时，为即将到来的敌方阶段恰好选择一条意图：
1. 蓄力重击，若合法。
2. 普通近战攻击，若合法。
3. 追击，若存在能缩短距离的合法步。
4. 待机。

选定的意图与全部目标参数在预告生成时捕获。执行期间不重跑 AI。后续战场变化可能使已捕获动作失效，但不得导致选择替代动作。

### 玩家反制

- 移出蓄力重击的标记格。
- 用一次成功的控制效果取消先锋当前预告。
- 在其执行槽位之前击败先锋。
- 用防御或保护技能缓解角色锁定的普通攻击。
- 利用障碍与站位阻止或推迟合法的追击/蓄力直线。

### 验收测试

1. 曼哈顿距离大于 2 时，先锋选择追击或待机，绝不选择攻击。
2. 清晰直线上距离 2 时，预告格子锁定的蓄力重击。
3. 正交相邻时，预告角色锁定的普通攻击。
4. 对角目标不算相邻，也不能被蓄力。
5. 先锋与蓄力目标之间存在墙体或障碍时，该重击不合法。
6. 普通攻击预告后移动目标，不改变角色目标。
7. 蓄力预告后移动目标，不移动标记格。
8. 击败先锋立即取消其预告。
9. 成功控制取消当前预告；失败控制保持不变。
10. 先前动作封锁了原始蓄力格时，重击取消，不重选、不回退到其他动作。
11. 等距与等血量并列在重复运行中始终一致裁决。
12. 可见意图与实际执行报告相同的动作 ID、目标模式、目标、作用范围与伤害。

### 调参备注

生命与伤害是首个可玩遭遇刻意保守的起始值。在视为平衡之前，必须对照守誓者最终的生命、防御、防御技能与另外两种敌人进行测试。

## 10.2 远程神射手 — 临时实现规范

> 状态：原型实现选择，不是单独经所有者批准的平衡规则。本节建立刻意小巧的首个实现供评审与实机测试；不扩大 Prototype 0.1 范围。

### 角色与教学目标

远程神射手制造一个远距离、可读的单格威胁。它教玩家利用掩体、切断射线，而不是把距离本身当作安全。

### 运行画像（临时调参值）

| 属性 | 初始值 | 备注 |
|---|---:|---|
| 生命 | 4（现值 2000） | 临时值；耐久低于先锋 |
| 攻击伤害 | 2（现按倍率结算） | 临时值 |
| 攻击射程 | 曼哈顿距离 3–6 | 仅正交直线 |
| 目标模式 | 格子锁定 | 对捕获格开火，不追踪角色 |
| 作用范围 | 单格 | 无溅射伤害 |
| 执行优先级 | 2 | 在先锋蓄力与普通近战之后 |

> **数值现状（2026-11-25）**：神射手现行属性为生命 2000、攻击 1200、防御 350、法抗 250（`data/enemies/marksman.tres`）；瞄准射击为 1.0× 物理（`intent_planner.gd`）。

### 动作 — 瞄准射击

- 仅当玩家在同一行或同一列、相距 3–6 曼哈顿格且整条射线无遮挡时合法。
- 墙体、障碍或中间的占用格阻挡射击。
- 捕获玩家当前格作为唯一受影响格。意图记录动作 ID `aimed_shot`、目标模式 `TILE_LOCKED` 与伤害预览。
- 预告确切的标记格与独特的射击标记；展示预期伤害。
- 执行时，仅对占据捕获格的存活玩家方单位结算。若该格为空，以 `marked_cell_empty` 取消；绝不追踪角色或重选目标。
- 执行时重新校验原射线。若新的阻挡使其非法，以 `marked_cell_line_blocked` 取消。
- 神射手不随此动作移动。

### 无射击回退

- 若规划时射程、对齐或射线要求不满足，生成显式 `wait` 意图。
- 若先前合法的射击在预告生成后变得非法，取消射击。不将其转换为待机、追击或其他攻击。
- 首个实现刻意省略转移与多格射击，以保持预告/执行契约可测。

### 玩家反制

- 在敌方阶段之前移出标记格。
- 在规则允许处用障碍或其他单位切断射线。
- 在其执行槽位之前击败或打断神射手。
- 不要假定对角对齐能构成合法射击。

### 验收测试

1. 清晰正交直线上相距 3–6 格的玩家产生瞄准射击意图。
2. 意图为格子锁定，捕获玩家原始格与既定伤害。
3. 射程外、对角或阻挡后的玩家不产生瞄准射击。
4. 移出标记格使射击取消且无伤害。
5. 移到别的格不导致射击追踪玩家。
6. 结算前射线被新阻挡占据时射击取消。
7. 被阻挡或射程外的神射手获得可见的待机意图。
8. 相同棋盘状态重复规划产生相同意图。

### 实现边界

*（原文）* 遭遇初始化接受与敌人格数组平行的可选兵种数组。省略该数组时保留既有全先锋测试布置。支持的值经过显式校验（`vanguard`、`marksman`、`area_controller`）；未知值或数组长度不匹配会在改动任何存活状态之前拒绝整个初始化。单位存储其兵种；意图生成与 UI 表现均读取该字段。敌人 ID 保留兵种前缀与原始遭遇索引。

*（现状注）* 该边界描述已被 M1 数据驱动重构取代：敌人属性现从 `data/enemies/marksman.tres` 加载（`enemy_catalog.gd`），关卡在 `data/levels/*.tres` 中声明 `enemy_archetypes` 数组并由 `level_catalog.gd` 校验加载；行为分支仍在 `intent_planner.gd` 中按兵种实现。

## 10.3 区域术士（区域控制者）— 临时实现规范

> 状态：授权委托下的原型实现选择。形状、射程、生命、伤害与优先级均为临时值，需实机测试；不扩大 Prototype 0.1 范围。

### 角色与教学目标

区域术士制造一个固定的、可规避的区域威胁。它教玩家读取多格预告，并在敌方阶段之前花移动离开受威胁的作用范围。

### 运行画像（临时调参值）

| 属性 | 初始值 | 备注 |
|---|---:|---|
| 生命 | 5（现值 2600） | 临时值 |
| 攻击伤害 | 1（现按倍率结算） | 作用于作用范围内的每个玩家方单位 |
| 有效射程 | 曼哈顿距离 2–4 | 规划时从术士量到玩家格 |
| 目标模式 | 区域锁定 | 捕获原始作用范围 |
| 作用范围 | 中心格及其正交邻格 | 最多五格；地图边界处裁切 |
| 执行优先级 | 1 | 与先锋普通近战同档；按稳定行/列/角色 ID 并列裁决 |

> **数值现状（2026-11-25）**：区域术士现行属性为生命 2600、攻击 1100、防御 450、法抗 650（`data/enemies/area_controller.tres`）；地脉脉冲为 0.7× 魔法伤害（`intent_planner.gd`），经目标法抗按递减收益公式减免。

### 动作 — 地脉脉冲

- 玩家相距 2–4 曼哈顿格时，捕获玩家当前格作为五格正交十字的中心：中心、上、右、下、左。
- 地图外的格子被省略。生成的受影响格列表固定于意图中。
- 动作使用 `ground_pulse`、目标模式 `AREA_LOCKED` 与临时伤害值。
- 执行时，对仍占据捕获格的每个存活玩家方单位造成伤害。
- 若捕获区域中已无存活的玩家方单位，以 `marked_area_empty` 取消。不移动区域、不重选目标、不选择替代动作。
- 玩家处于 2–4 规划射程之外时，生成显式 `wait` 意图。
- 首个实现不含视线要求、移动、持续危害、状态效果或多回合区域。

### 玩家反制

- 读取全部高亮格，而不仅是中心标记。
- 在结束回合之前用移动离开整个十字作用范围。
- 在其执行槽位之前击败或打断区域术士。

### 验收测试

1. 曼哈顿距离 2–4 的玩家产生区域锁定的 `ground_pulse` 意图。
2. 意图捕获固定的十字作用范围与既定伤害预览。
3. 边界格被裁切，不产生越界格。
4. 留在作用范围内的玩家承受捕获的伤害。
5. 离开作用范围的玩家不受伤害，意图以 `marked_area_empty` 取消。
6. 规划射程之外的玩家产生可见的待机意图。
7. 结算绝不重定中心或悄悄选择其他动作。

### 实现边界

*（原文）* 遭遇初始化接受 `area_controller` 作为第三种显式兵种。单位存储该兵种；战斗 UI 使用独特的 `C` 标记并从意图记录渲染每个捕获的区域格。全部数值与十字作用范围在运行时实机测试前保持临时。

*（现状注）* 数值现由 `data/enemies/area_controller.tres` 提供；行为分支在 `intent_planner.gd`。

## 11. 失败处理

- 无法创建意图时，记录带原因的规划失败。
- 意图失效时，仅应用已批准的回退策略。
- 绝不允许被击败的敌人执行动作。
- 绝不在来源敌人阵亡后遗留陈旧预告。
- 绝不悄悄重选目标。
- 发生意外的运行时错误时安全失败：不发明新的攻击结果；记录失败，并尽可能保留可恢复的战斗状态。这并不意味着把局内进度写入磁盘。

## 12. 测试与验收要求

1. 玩家回合开始时，若遭遇规则要求，每个合格的普通敌人恰好获得一条有效意图。
2. 每个展示的预告均派生自其意图记录。
3. 每个执行的敌方动作使用同一份意图记录与动作定义。
4. 展示的目标、区域、伤害与效果与实际执行一致。
5. 向玩家展示的敌方执行顺序与实际执行顺序一致。
6. 玩家回合内击杀敌人立即移除其预告。
7. 被击败的敌人绝不行动。
8. 失效意图遵循已文档化的回退，且绝不被悄悄替换。
9. 重叠预告可在手机尺寸的横屏显示上逐个检视。
10. 重复遭遇不产生陈旧预告、重复敌方动作或软锁。

**已确认的控制/预告交互：** 当控制效果成功打断敌人时，该敌人的当前预告立即取消。若控制尝试失败，其预告保持不变，敌人按计划行动。控制效果只更改受影响敌人的预告，不改变其他敌人的意图。

**已确认的敌方执行顺序：** 敌人以固定的确定性顺序执行。按预定义的敌人动作优先级排序；优先级并列时按稳定的战场位置顺序。在敌方阶段开始前向玩家展示完整顺序，并在该阶段内保持固定。

**已确认的先手战场变化处理：** 后续敌人保持其已预告的目标模式与目标。角色锁定的动作继续追踪同一角色；格子锁定的动作在原始格结算；区域锁定的动作在原始区域结算。若后续动作因战场变化（例如所需路径或条件不复存在）而确实无法执行，则取消该动作。绝不悄悄选择新目标或生成替代攻击。

**已确认的地形变化交互：** 既有预告在地形变化后保持不变。若原动作仍可执行，则按原目标与区域结算。若地形变化使其无法执行，则取消。地形变化绝不悄悄扩大攻击区域或更改其目标。

**已确认的无合法动作回退：** 若敌人的预告动作在结算时无法合法执行，取消该动作。不选择新目标、不切换技能。不退还或补偿玩家 AP。在战斗日志/调试事件中记录取消原因供检视。

**已确认的 Prototype 0.1 动作选择方向：** 使用简单的确定性优先级 AI。意图生成期间先检查符合条件的特殊动作，其次普通攻击，最后以移动或待机作为最终回退。同一优先级内存在多个合法选择时，用固定的确定性并列规则选择，而不是重新随机选择。意图一经生成并预告，本回合内计划保持固定；结算器不得在执行时重跑无约束的目标或技能选择。每种敌人的确切动作优先级与并列键在敌人内容规范中指定。

## 13. 实现前需决策

1. 为 Prototype 0.1 的每个敌方动作分配角色锁定、格子锁定或区域锁定；混合目标模型整体已确认。
2. 格子锁定或区域锁定的动作在预告生成之后是否有额外的射程/视线失效条件。
3. 控制成功/失败的确切条件、抗性数值与时长/效果细节（由相关技能与战斗规则定稿）。
4. 每种敌人确切的动作优先级表与确定性并列键。
5. 可变伤害或条件效果的确切预览格式。
6. 预告重叠的检视与分层行为。

*（现状注：第 1–2 项已由各敌人规范与 `intent_planner.gd` 落地；第 3 项对应守誓者 V2 的绝对守护（嘲讽+反击），见 `docs/design/characters/OATHKEEPER_V2_DESIGN_SPEC_v1.0_zh-CN.md`；第 4–6 项以当前实现为基线，待实机验证。）*
