## 一、当前阶段

**当前可玩范围包括瑟弗林的三关战斗教学、樱的春之境普通和困难探索、黄昏补给商行。** 模块关系见 [当前架构](ARCHITECTURE.md)，自动化验证见本文验证记录与 [工程基线](BASELINE.md)。

本次重构核心落地内容：
- **2.5D 表现与界面**：8×8 等距斜视角石板棋盘 + `Q/E` 四对角 90° 旋转视角、主角机能二次元少女「瑟弗林」4 向动态朝向立绘与大头头像、遗迹构造体三职业立绘、新主菜单与清爽战斗 HUD（左下头像血条、底部 4 技能条悬停说明、右上敌方行动与充能情报卡、危险格红晕压迫滤镜）。
- **核心战斗机制**：单人瑟弗林每回合 `3 AP`、4 技能重做（`誓刃` 击退 1 格并平移重算敌方攻击区、`裁决印记` +30% 易伤消耗、`誓盾庇护` 一键瞬发 650 盾、`绝对裁决` 4 能量周围 1 格重击击退）、**AP 联动敌方技能充能**（玩家每耗 1 AP 敌人充能 +1，满 3/3 放大招）、分步敌方回合演出与多怪目标分流。
- **遗迹宝箱与装备背包循环**：每关 2 个随机战利品宝箱（武器/护甲/消耗品/技能升级）；敌人拆箱会对称穿上装备或用掉道具，击败后仅掉落武器/护甲至地面可拾取；通关自动开启完好宝箱入包；`[B]` 键随时穿戴/卸下/使用，整局结束后 `RunState.reset()` 清空。

**2026-11-27 补充：「未尽之春」的春之境已可完整走完一局（设计汇总 §7 / §8 / §9 / §10 / §11 / §13 / §14 / §15 / §16）。**

- **模式入口与边界**：从主菜单进入营地大厅，在「选择地图」中进入教学遗迹或春之境；两种模式共享局外工坊，分别维护局内资源（§4）。
- **地图**：5×5 三套模板，每套 11 个固定地点 + 0～1 个隐藏地点。文档给定锚点（三套 Boss 坐标、模板 2 的 (5,4)、起点到 Boss 8/6/7 格）为硬数据；其余逐格坐标由 `LAYOUT_ORDER` 确定性生成并标注**草案**。
- **探索**：体力 10 点、曼哈顿成本、原子移动、恰好耗尽保留一次交互窗口、主动结束作废余量。
- **战斗**：20 套遭遇（§13 十二场、§14 五场、§15 三场）；精英与 Boss 用文档「下调 30% 后」的最终属性；开战前有 §11.1 部署阶段（南侧三行选位、不耗 AP 不计回合、确认后开战）。地图 → 战斗 → 回地图闭环打通，胜利保留位置与体力并继承生命，失守节点灰显、每区域可用 3 补给续行一次（回复三成）。
- **事件**：十个事件 + 隐秘之地，选项带条件与效果，风险四档且掷骰按（种子, 事件, 选项）定种；经济事件只作用于下一家商店。
- **商店**：春日行商，买入 / 出售 / 服务三页；库存锁定、买过不再上架、刷新费递增、交易原子、出售价独立计算。
- **结算与存档**：胜利按存活宝箱结算花钿；精英三选一藏品；Boss 随机一件并结束春之境。区域解锁独立持久化；后续区域只有在已解锁且场景真实存在时才会交接，否则安全结束并提示原因。存档含生命、装备背包、藏品遗物、商店库存、购买记录和仍待处理的事件及战后选择，恢复不重抽。

## 二、目标范围

Prototype 0.1 的目标内容：

- 一名可操作角色：守誓者瑟弗林（Sevrin）。

## 四、待办任务（按优先级）

### P0｜猎人通灵（原「猎人同伴」）

**状态：已完成**——实现、自动化测试与无头运行均已通过；桌面人工操作确认并入 P1 一并检查。

**设计定位**：猎人不是常驻战场的单位，而是一个**通灵技**。施放后猎人出现在目标身旁、完成一次突袭后立即离场，不占用行动点，也不在战场上留下任何东西。

**规则**：

| 项目 | 规则 |
|---|---|
| 施放方式 | 技能栏第 5 项（数字键 5），选中后点击任意存活敌人 |
| 出现位置 | 目标周围第一个空闲正交邻格，顺序固定为上、右、下、左 |
| 存在时长 | 一击即走：结算完伤害即离场 |
| 代价 | **不消耗行动点** |
| 节流 | 两回合冷却（第 1 回合使用后，第 3 回合才可再次使用） |
| 不生成单位 | 不占格、不进入敌方行动顺序、不会被敌人锁定 |
| 失败条件 | 目标已阵亡 / 非敌人 / 四周无空位 |

**完成标准**：

- [x] 通灵技出现在技能栏并可通过数字键 5 选择
- [x] 施放后不消耗行动点
- [x] 两回合冷却正确计数与重置
- [x] 猎人不生成战场单位、不占格、不进入行动顺序
- [x] 目标四周无空位时施放失败，且不进入冷却
- [x] 被拒的施放不造成伤害、不重启冷却
- [x] 击杀最后一个敌人时正确触发胜利
- [x] 自动化测试通过（`tests/test_hunter_summon.gd`，39 条断言，Godot 4.7.2 headless）

**数值基线**（待实测调整）：攻击 1400、倍率 0.9，即原始伤害 1260；对近战先锋（防御 700）实际造成 741 点伤害。

## 七、协作与提交要求

每项开发任务开始前，先确认目标分支、最新 Commit 和相关文件。

- 当前原型开发主线：`main`（默认分支，内容与可运行状态一致）。
- 新任务优先使用独立功能分支开发，再通过 Pull Request 合并。
- 不要直接把未审查的改动提交到 `main`。
- 每次改动说明修改文件、改动目的和影响范围。
- 源码变化后同步更新相关文档和测试。
- 提交时记录完整 Commit SHA。
- 测试包必须注明它对应的 Commit SHA。
- 分别记录静态检查、Godot 导入、自动化测试、桌面实测和设备实测；没有执行的项目标记为「待验证」。
- ECHO 与「拾光」项目严格隔离。
- 不擅自覆盖或替换朋友已经发布的测试包。

## 八、每项任务的状态定义

- **待开发**：功能尚未实现。
- **开发中**：正在修改或接入。
- **待验证**：代码看起来已具备，但还没有完成对应环境的实际测试。
- **已完成**：达到该任务的完成标准，并有相应验证记录。
- **暂缓**：明确不属于当前阶段，暂不安排。

> 更新本文件时，应优先维护上面的任务状态和完成标准。详细的历史过程、设计决定和测试步骤分别保留在各自的专题文档中，避免本文件再次变成冗长的开发日志。
