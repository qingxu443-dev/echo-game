# ECHO 后续任务清单

建立日期为 2026-11-27，依据 main 的 a7c095b 及其后续结构与规划分析。近期交付目标为稳定的 Windows 试玩版。以下条目初始状态均为未开始，标记「待决策」或「暂缓」的条目在条件落实后排期。

## 使用方式

- 每项任务有固定 ID，实施 PR 引用对应 ID。负责人由接手者登记。
- 完成时记录源码提交、验证结果、PR 和实际工时，再勾选任务。
- 工程估算包含实施、针对性验证、全量回归、文档与集成，每人日约六小时有效开发。
- 阶段估算按工作包计，子任务共享验证与集成时间。新增内容与设计等待时间需要重新估算。
- 任务清单供 agent 本地协作。单独设定或调整清单时留在本地，实际实施产生可验证成果后再同步 PR。
- 每次实施先 fetch 并核对最新 main 和开放 PR，从 main 新开分支。全量回归通过后开 PR，双端 CI 成功且 mergeable_state=clean 后合并，删除本轮分支。
- 断言变化同步 BASELINE 的总数与合计，以及守卫扫描的文档副本。
- 完成记录使用「ID / 负责人 / 提交 / 验证 / PR / 实际人日」格式。

教学三关、樱与瑟弗林技能、春之境三模板及两种探索模式、事件行商、工坊补给、单局恢复、棋盘四机位和 Windows 导出已有实现。既有测试与 CI 结果见 [BASELINE](BASELINE.md)。M0–M2 早期重构、表现层拆分、CI 和 D-01 参数化已有实现，更新旧文档时标记其实际完成范围。

## M1 预告与存档可靠性

- [x] **ECHO-101 · P0 · 修正多次命中伤害汇总**。依赖 003。按行动顺序计算护盾及其他会变化的防御状态，保持预览只读。验收为两次各 1000 伤害对 400 护盾正确汇总扣血 1600，并覆盖护盾耗尽、完全吸收、混合伤害、降防先后与目标阵亡。验证见 `test_intent_preview.gd`。临机追身与拦路截击的警戒覆盖由 ECHO-205 处理。
- [x] **ECHO-102 · P0 · 工坊与探索跨文件事务设计**。依赖 001。明确补给领取、教学出征、战后残晶和探索检查点的提交顺序、事务标识及恢复策略。验收为每个中断点有唯一恢复结果，兼容已有两份 JSON。春之境采用先记录两个目标的完整结果、再依次写入和清理记录的方案。教学首场遭遇初始化成功后领取，其后沿用局内状态退出语义。
- [x] **ECHO-103 · P0 · 实现事务恢复与幂等结算**。依赖 102。实现事务记录及启动恢复，传播失败状态。验收为每次写入前后失败、重启、同一结果重放均无重复奖励或补给损失。春之境出征和结算已实施并通过故障验证，教学首场初始化失败保留打包栏，成功后只领取一次。
- [x] **ECHO-104 · P1 · 存档边界校验与恢复提示**。依赖 102。校验版本、嵌套类型、坐标长度和边界、内容 ID、资源范围及待决事项。验收为旧档可迁移，损坏档保留并给出诊断，加载失败可被调用方识别。
- [x] **ECHO-105 · P1 · 存档故障回归**。依赖 103、104。验证文件无法写入、替换失败、截断 JSON、未来版本、连续保存和恢复中的事件/领奖/续行。验收为回归使用独立路径，真实玩家存档受到隔离。

## M2 新战术机制回归

- [x] **ECHO-201 · P1 · 容忍反击与多段计次**。依赖 003。验收为近战按施法计次、远程不累计、阈值反击仅触发一次，回合和遭遇重置正确。已通过 `test_tactical_pressure.gd` 的正常技能请求与回合入口验证。
- [x] **ECHO-202 · P1 · 护甲破坏与结界联动**。依赖 201。验收为普通攻击削甲、重击破甲、碰撞与拆节点行为符合规则，破甲易伤及期限正确。已修复普通多段与终极技逐段重复削甲：普通和重击各按目标/施法序号计次，碰撞与拆节点独立生效。`test_armor_break.gd` 覆盖多目标、易伤窗口、结界防御及新旧 JSON 快照。
- [ ] **ECHO-203 · P1 · 击杀返 AP 与资源顺序**。依赖 201。验收为单杀、群杀、最后一敌、每回合上限和回合切换正确，返 AP 与剑意/能量的记账顺序稳定。
- [ ] **ECHO-204 · P1 · Boss 二阶段与双动**。依赖 202、203。验收为半血跨阈值只触发一次、护卫占格合法、无空位安全处理，两次动作预告和实际执行一致。
- [ ] **ECHO-205 · P1 · 临机追身和预告契约**。依赖 003、101。明确允许转向/追步的动作，验证阻挡、距离、失效取消和警戒格提示。验收为合法例外可见，界面提示范围与结算条件一致。
- [ ] **ECHO-206 · P1 · 正常入口集成**。依赖 201–205。通过玩家请求、结束回合、结算和重开驱动场景。验收为两角色、Boss 与道具组合中状态正确，测试具有明确行为预期。

## M3 教学与春之境验收

- [ ] **ECHO-301 · P1 · Windows 交互检查**。依赖 101。核对窗口缩放、鼠标键盘、焦点、取消、旋转、背包、部署及提示。验收为选定分辨率和显示缩放下无关键遮挡或无法操作，记录设备与提交。
- [ ] **ECHO-302 · P1 · 教学三关验收**。依赖 301、206。走通胜利推进、失败重开、角色技能和宝箱教学。验收为新玩家能理解移动、预告、击退与充能，并记录教学卡点和修正。
- [ ] **ECHO-303 · P1 · 三模板双模式整局验收**。依赖 105、206、301。核查实际主路线 18 场遭遇、事件伏击、行商、隐藏点、结局、困难绘线与自动推进。验收为每模板普通/困难均有完整整局记录，额外精英目录有单场验证记录。
- [ ] **ECHO-304 · P1 · 正式经济与奖励参数**。依赖 003、303。确认普通敌人数值、花露用途与容量、商品/刷新/售价、战斗奖励概率、失败转化和 Boss 续行。验收为明确区分已定参数、实测结果和仍待定事项，新增规则获得设计结论。
- [ ] **ECHO-305 · P1 · 补给与难度平衡**。依赖 302–304。测试无限量补给、失败保底、重复挑战收益、Boss 重甲和双动。验收为记录通关时长、失败原因、补给消耗和残晶收支，据此完成首轮调参。
- [ ] **ECHO-306 · P1 · 玩家反馈复测**。依赖 305。修正阻断、严重误导和明显难度异常，按原场景复测。验收为已知问题列表带复现、严重程度、状态及接受理由。

## M4 结构收敛

- [ ] **ECHO-401 · P2 · 接续 BattleLedger**。依赖 002、206。复用并行分支成果，收拢机制账本和重置入口。验收为跨回合/跨遭遇清理一致，同时核对 TacticalPressure 的静态实例索引账本生命周期。本轮已移除该静态索引，压力序号和返 AP 额度改由 BattleLedger 持有，兼容旧暂停档；本项其余集成依赖仍待 ECHO-206。
- [ ] **ECHO-402 · P2 · 地图流程协调**。依赖 103、401。提取场景切换、待决交互和保存调度，由场景显式提供依赖。验收为地图视图职责减少，正常进入、返回、恢复和失败路径保持正确。
- [ ] **ECHO-403 · P2 · 战斗与局外边界**。依赖 103、401。把战斗中的模式判断、工坊奖励移到流程协调层。验收为战斗规则可在独立场景运行，教学和春之境奖励各结算一次。
- [ ] **ECHO-404 · P2 · 击退实现收敛**。依赖 202、401。先固定两路径的碰撞、事件、预告同步与击杀行为，再共享可复用逻辑。验收为墙、单位、宝箱、边界和多步击退通过针对性回归。
- [ ] **ECHO-405 · P2 · 输入和接口类型**。依赖 301、402。用 InputMap 命名动作统一入口，加强跨场景载荷与公共方法类型。验收为四机位点选、技能与取消不回归，错误载荷在边界拒绝。
- [ ] **ECHO-406 · P2 · 配置与工具可复现性**。依赖 001。核对技能说明与目录来源、整理需要编辑器调整的参数，锁定素材工具依赖。验收为参数有真实读者，代表性素材处理可以复现。
