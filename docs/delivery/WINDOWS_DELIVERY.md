## 从指定提交构建

工具为 PowerShell 7、Git、Python 3 标准库及 Godot **4.7.2 Standard Windows x64 console**。运行游戏无需这些工具。导出模板固定为同版官方 Windows release x86_64，SHA-256 为 `d34d36f3be1a6c49c56525ae86469b92e4f417ddf0b43cf00dd80c385c4b0562`。

```powershell
git checkout <待验收提交>
git status --short  # 指定提交交付要求无未提交改动
python tools/fetch_windows_template.py
./tools/build_windows.ps1 -Godot 'C:/Godot/Godot_v4.7.2-stable_win64_console.exe'
```

下载器从固定的 Godot 官方模板 ZIP 按字节范围读取 Windows release 成员（压缩后约 38 MB），核对 ZIP CRC、版本和最终 SHA-256；服务端拒绝范围请求时直接失败，不静默下载整个约 1.28 GB 模板包。代理/限流失败可重试。已有匹配模板时先校验缓存，不联网。也可用 `-Template <模板路径>` 显式指定同一校验值的模板。

构建器使用独立 `.godot/build-profile` 作为 APPDATA，依次导入资源、执行全量套件和守卫、导出 release、挂载 exe 的内嵌 PCK 核查内容，再运行 exe 的无界面启动检查。`custom_template/release` 只在构建期间替换，正常/异常退出均恢复预设与 APPDATA。此隔离目录不读取或覆盖玩家原存档。

输出默认在 `build/windows/`，也可用 `-OutputDir build/my-candidate`：

| 产物 | 用途 |
|---|---|
| `ECHO_Windows_x64.zip` | exe、README、manifest、资源清单与日志的交接包 |
| `ECHO_Windows_x64.exe` | 内嵌 PCK、x86_64、未代码签名的程序 |
| `manifest.json` | 源码 SHA、脏工作区标记、引擎/模板版本、exe SHA-256、自动检查和待人工状态 |
| `package-content.json` | 实际挂载后的资源路径；拒绝 tests、素材源图、tools、docs，以及缺失主菜单 |
| `logs/*.log` | import / suites / export / contents / smoke 五步输出；非零退出或引擎脚本错误即失败 |
| `README.txt` | 测试者无需仓库即可阅读的操作、已知问题、反馈与回滚说明 |

每次重新构建先撤销上次成功 manifest，避免失败后误交旧清单。只有命令成功、manifest 与 exe 校验一致且 `source_dirty=false` 的包才可送指定提交验收。不要把单独旧 exe、旧 ZIP 或失败日志当成本次构建。这里的可重复指同一套固定工具和检查能从指定提交构建，不承诺 exe 的二进制时间戳逐字节相同。生成物和模板缓存不入库。

首次真实工程验证：Windows / Godot `4.7.2.stable.official.ed1daf0bf`，五步均成功，实际包内 320 个资源路径，exe 约 107 MiB；模板匹配、测试/源图/工具/文档均未打入 PCK。最终待验收提交和 exe 校验值以交接包 manifest 为准。该记录是构建与无界面启动证据，画面、输入和性能仍待下面的人工记录。
