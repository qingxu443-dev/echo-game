## 甲类｜伤害与属性（阻塞模块 E）

### 待决 1｜樱的 RES 百分比与整数抗性公式的对应

**事实**：当前实现为整数递减收益公式 `最终 = ⌊原始 × 1000 ÷ (1000 + 抗性)⌋`（`combat_math.gd`，已被全部测试采用）；樱候选面板 RES 为 **10%**。§10.5 给出换算：10% ≈ 抗性 111.11 点。

| 选项 | 方案 | 影响范围 |
|---|---|---|
| A | 全盘改为百分比抗性公式 | 重写伤害管线与全部数值、测试大改 |
| **B（建议）** | 内部保留整数公式，樱 RES 落为 111 点，展示层换算显示为 10%；建立「RES% ↔ 点数」统一换算表（`R = 1000 × p ÷ (1 − p)`） | 仅数值文档与角色数据文件 |
| C | 双轨并存 | 两套公式，违反「单一伤害入口」要求（§10.6） |

**建议 B 的理由**：公式已被 17 套件验证，改动面最小；百分比只是表达习惯，点数才是结算单位；换算表一次性解决后续所有角色的 RES% 表达。

**裁决（2026-11-26）**：☑B — 内部保留整数公式，樱 RES 落 111 点，展示层换算为 10%。☐A ☐C

**落地**：`CombatMath.resistance_percent()` 已就位并有断言（111 → 9.99%）；`sakura.tres` 的数据本就已生效。HUD 目前不展示 RES，故还没有调用点，函数等 UI 需要时直接接入。

### 待决 2｜0.3 最终伤害类型定义

**事实（裁决前，2026-11-26 核对）**：PR #23 已将伤害类型**封闭为白名单**，未知类型不再静默走 0 抗性分支绕过防御。当时白名单**只有两种类型**——物理 / 法术（`damage_types.gd:14-19`），真实伤害被 `test_damage_types.gd` 显式断言拒绝（`"true"` 在任何伤害落地之前即被挡下）。原文「三类型为物理 / 法术 / 真实」与当时的代码不符，已更正。

**依赖**：真实伤害能否入白名单取决于**待决 3**。本项必须排在 3 之后。

**裁决（2026-11-26）**：☑ 确认**三枚举**（物理 / 法术 / 真实）。待决 3 定为 C，真实伤害合法化，白名单随之扩为三类，仍为封闭集合、仍拒绝未知类型。

**落地**：`damage_types.gd` 增 `TRUE_DAMAGE` 与 `ignores_mitigation()`，`describe()` 输出三类；`test_damage_types.gd` 相应从 13 条扩为 24 条。

### 待决 3｜真实伤害是否受通用减伤与护盾影响

**事实（裁决前）**：当前伤害管线顺序（§10.3）：类型抗性 → 百分比减伤 → 最终减伤 → 护盾 → HP。当时真实伤害没有角色技能使用，且被封闭白名单挡在伤害落地之前，规则空白。

| 选项 | 方案 | 语义 |
|---|---|---|
| A | 只跳过 DEF/RES，其余全部照走 | 真实伤害仍受减伤状态与护盾影响 |
| **C（建议）** | 跳过 DEF/RES 与全部百分比减伤，**仍受护盾吸收** | 「真实」= 无视防御数值；护盾是显式资源屏障，不是防御数值 |
| B | 无视一切，直扣 HP | 真实伤害绕过护盾会削弱护盾系统的可信度 |

**建议 C 的理由**：护盾「优先于 HP 承伤」是 §11 已确认方向，绕过护盾会破坏该承诺；同时保留「真实」无视防御数值的核心卖点。

**裁决（2026-11-26）**：☑C — 跳过 DEF/RES 与全部百分比减伤，**仍吃护盾**。☐A ☐B

**落地**：`DamageTypes.ignores_mitigation()` + `battle_actor.apply_damage_with_result` 的单一分支；护盾吸收对三种类型共用同一段代码，不存在第二套入口。断言见 `test_damage_types.gd` 的 `_test_true_damage_ignores_mitigation_but_not_shield`（含同条件物理伤害的对照组）。

### 待决 4｜暴击是否进入 Prototype 0.1

**事实**：§9 已定「普通攻击默认不带随机暴击」；§34 模块 E 列有「暴击接口」；当前代码无暴击。2026-11-26 全仓检索 `crit` **零命中**，故 A 的「管线预留判定位」是新增一处钩子，不是确认既有接口。

| 选项 | 方案 |
|---|---|
| **A（建议）** | 接口先行：管线预留暴击判定位（固定条件触发、倍率由技能定义），Prototype 0.1 无任何技能赋予暴击 |
| B | Prototype 0.1 即实装至少一个暴击来源 |

**建议 A 的理由**：与 §49 范围冻结「优先建立扩展接口，不提前实现完整系统」一致；留接口不增加当前测试负担。

**裁决（2026-11-26）**：☑A — 只留接口，Prototype 0.1 没有任何技能赋予暴击。☐B

**落地**：`apply_damage_with_result(..., crit_multiplier := 1.0)`，倍率在抗性之前作用于原始伤害，结果多一个 `was_critical` 字段；默认 1.0 时数值与改动前完全一致，故全部旧断言不受影响。触发条件留给技能，管线只负责放大。

## 乙类｜多段攻击与目标（阻塞模块 F 与樱技能细化）

### 待决 5｜多段攻击中目标倒地后，后续段如何处理

**事实**：§29 已有方向「范围技能不能因一个目标死亡而错误取消其他合法目标」「后续段必须由技能规格决定」。当前管线逐段结算、每段独立（§26-B）。

**建议默认规则**（技能规格可覆盖）：敌方目标死亡 → 该目标后续段全部跳过，**其他目标照常**；友方目标倒地 → 同样跳过后续段。

**裁决（2026-11-26）**：☑ 采纳默认规则。

**落地**：追认。`_apply_segments`（`character_skill_runtime.gd:452-456`）本就逐段判存活、跳过死者，`_apply_one_hit:462` 另有二次防护；本批未改。

### 待决 6｜群体技能是否继续处理其他存活目标

**事实**：与待决 5 联动；无尽芳华十字范围、落英 3×2 矩形均为多目标技能。

**建议**：**继续**——每个目标独立判定合法性（存活、占格、条件），单个目标失效不传染。

**裁决（2026-11-26）**：☑ 继续。

**落地**：追认。每个目标独立判存活，单个目标失效不传染；本批未改。

### 待决 7｜回锋的检查时点与目标记录方式

**事实**：§21 建议「多段攻击在整套攻击行动结束后统一检查回锋」；§30 结算顺序第 6 步把回锋处理放在击败事件之后、剑意获取之前；PR #23 后角色框架已在行动生命周期中预留了段/目标/行动三级区分（§28）。

| 选项 | 方案 |
|---|---|
| **A（建议）** | **行动级统一检查**：一次攻击行动全部段结算完成 → 一次性收集符合条件的残香目标（目标级每目标至多一次）→ 统一触发回锋 |
| B | 段级即时检查：每段命中后立即触发回锋 |

**建议 A 的理由**：§21 原文即建议此方案；统一检查天然防循环（§31），且与 §30 顺序吻合，测试可预期。

**裁决（2026-11-26）**：☑A 行动级统一检查。

**落地**：追认。`_endless_bloom`（`character_skill_runtime.gd:262-270`）在全部段结算后才循环已标记目标触发回锋；穿花、流风为单目标技能，同样在段后检查；本批未改。

### 待决 8｜流风极意第二段追击与回锋的精确结算顺序

**事实**：§22 极意流风 = 突进斩击（80%）+ 第二段追击（40%，可选新方向与新目标）；若目标已有残香，同一次行动最多触发一次回锋（50%）。

**建议**：追击视为**同一行动的第二段**，按待决 7 的行动级统一检查执行回锋——即回锋在两段全部结算后统一触发，不做段间即时回锋；「同一次行动最多一次回锋」按目标级计数。

**裁决（2026-11-26）**：☑ 采纳。

**落地**：追认。`_flowing_wind` 在极意时先补 40% 第二段（`EXTREME_FOLLOW_UP_MULTIPLIER`），随后才做一次回锋检查，正是行动级；「新方向/新目标」这一步界面还没有第二次瞄准入口，代码注释里已注明复用原目标。本批未改。

## 丙类｜资源与状态（阻塞模块 G 与樱资源结算）

### 待决 9｜普通攻击是否属于额外终极能量的主动行动

**事实**：§13「成功主动行动后每名角色每回合最多额外获得 1 点」未明确普攻是否计入。§19 中普攻**计入**剑意获取（攻击行动）。

| 选项 | 方案 |
|---|---|
| **A（建议）** | **计入**：普攻是主动行动，获得终极能量额外 1 点（受每回合 1 点上限约束） |
| B | 不计入：只有技能行动获得 |

**建议 A 的理由**：与剑意的「攻击行动获得剑意」保持同一「主动行动」语义，避免出现同一行动对两套资源身份不同的规则分叉；每回合上限已防止刷能量。

**裁决（2026-11-26）**：☑A 计入。

**落地**：`_basic_attack` 在剑意入账之后补一次 `gain_active_energy`；每回合上限在 `gain_active_energy` 内部，连续普攻不会刷出第二点。断言见 `test_battle_controller.gd` 的 `_test_normal_attack_pays_ultimate_energy`。

### 待决 10｜极意消耗后新剑意的结算顺序

**事实**：§30 已给出完整顺序建议（步骤 8：先执行极意消耗 → 步骤 9：按事件顺序发新剑意 → 步骤 10：检查 4 层与每回合 3 层上限）。

**建议**：确认 §30 顺序为正式规则——**先消耗、后获取**，消耗后的本行动新剑意不受消耗影响、正常计发。

**裁决（2026-11-26）**：☑ 确认 §30——先消耗、后获取。

**落地**：追认。`_falling_petals` 与 `_flowing_wind` 都是先 `_consume_extreme` 再 `gain_intent_from_action`，本次行动赚到的层数不受消耗影响；本批未改。

### 待决 11｜击杀、回锋与攻击行动同时发生时的剑意事件顺序

**事实**：§19 剑意来源：攻击行动 +1、击杀 +1、每回合首次回锋 +1；全部计入每回合行动获取 3 层上限。

**建议**：按 §30 步骤顺序计发——击败事件（步骤 5）→ 回锋（步骤 6）→ 剑意事件统一按 **行动 → 击杀 → 首次回锋** 顺序入账，三者合计仍受 3 层上限与 4 层存量约束。事件顺序写入测试用例（§40）。

**裁决（2026-11-26）**：☑ 采纳 §30 顺序（行动 → 击杀 → 首次回锋）。

**落地**：**部分实现**。剑意目前只有「行动 +1（受每回合 3 层预算）」与「回合开始 +1（预算外）」两个来源；击杀 +1 与每回合首次回锋 +1 **尚未入账**。本批不实施——它只影响节奏，不改变任何现有断言；补的时候要同时动 `test_character_framework` 的节奏断言与本文件基线。

### 待决 12｜残香 3 个敌方回合的边界计时方式

**事实**：§20「残香持续 3 个敌方回合」「重复施加只刷新持续时间」；§20 末要求映射到敌方回合边界且连续回合测试不多算不少算。

| 选项 | 方案 | 边界语义 |
|---|---|---|
| **A（建议）** | 施加/刷新发生在玩家回合 N → 记录到期边界为**敌方阶段 N+3 结束时** | 玩家可确定性推算：本次与后续两次敌方阶段内有效，第三次敌方阶段结束消失 |
| B | 以「敌方阶段开始时」检查 | 容易在第三个敌方阶段的首个意图前就消失，比直觉少算半拍 |

**建议 A 的理由**：与现有状态系统的 expiry_boundary（按阶段边界到期）机制同构，`battle_status_collection` 已有实现与测试可复用。

**裁决（2026-11-26）**：☑A — 到期边界为「玩家回合 N 的敌方阶段 N+3 结束时」。

**落地**：追认。残香用 `enemy_turns_remaining = 3` 计数，`tick_enemy_phase` 在敌方阶段边界递减、归零即移除，语义与 A 等价。它与 `expiry_boundary` 机制并存属历史原因，两者不冲突；日后若要统一，改的是实现，不是规则。

### 待决 15｜护盾重复施加的通用规则是否跨角色统一

**事实**：§11「默认不叠加、特殊技能可突破、重复获得的覆盖/刷新/替换仍需批准」；现有 `battle_status_collection` 已实现 replace / refresh / add 三种叠层策略；守誓者誓盾（v2）现为替换语义。

**补充（裁决前核对）**：三种策略当时的**默认值是 `STACK_REFRESH`**（`battle_status_collection.gd:18`），不是 replace，所以采纳 A 不是零成本——要改默认值并回归全部护盾相关断言。

| 选项 | 方案 |
|---|---|
| **A（建议）** | 通用默认 = **replace**（新护盾值替换旧值，持续时间重置）；技能可显式声明 refresh 或 add 突破；不得把守誓者 15% 最大 HP 上限自动推广为全角色规则（§11 已明令） |
| B | 每技能各自定义，无全局默认 |

**建议 A 的理由**：全局默认保证可预期，技能声明制保留突破空间；复用现有三种叠层策略实现，零新增机制。

**裁决（2026-11-26）**：☑A — 通用默认 = replace，技能可显式声明 refresh / add 突破；守誓者 15% 上限不推广为全角色规则。☐B

**落地**：`apply_status` 的 `stack_policy` 默认值改为 `STACK_REPLACE`。残香本来就显式传 `refresh`，誓盾显式传 `replace`，故现有行为不变；`test_battle_status.gd` 新增「省略策略时表现为 replace」的断言（先把层数堆到 3，refresh 会留 3、replace 会归 1，可判别）。

### 待决 16｜落英极意的「攻击范围扩大」具体数值

**事实**：§23 极意强化只写"攻击范围扩大"，未给数值。当前实现取**宽 +1、深 +1**（基础 3×2 → 极意 4×3），常量 `EXTREME_SHAPE_WIDTH_BONUS` / `EXTREME_SHAPE_DEPTH_BONUS`。

| 选项 | 方案 |
|---|---|
| **A（当前实现）** | 宽 +1、深 +1，3×2 → 4×3 |
| B | 仅深度 +1，3×2 → 3×3（向前更远） |
| C | 仅宽度 +1，3×2 → 4×2（横向更宽） |

**影响**：只改两个常量，不涉及判定逻辑；黄圈与施放读同一尺寸，改完自动一致。

**裁决（2026-11-26）**：☑A 保持现状（宽 +1、深 +1）。

**落地**：追认。`character_skill_runtime.gd:47-48` 两个常量均为 `1`，黄圈与施放读同一尺寸；本批未改。
