## 已发生问题与预防

| 已发生问题 | 预防规则 |
|---|---|
| Godot 无法推断 Dictionary 局部变量类型 | 对 Dictionary、Array、节点引用及复杂表达式显式标注类型 |
| 方法返回值参与推断导致解析失败 | 公共方法声明明确返回类型；复杂推断优先改为显式类型 |
| 静态类型不匹配（例如泛型数组传参） | 函数签名、数组元素类型与调用点保持一致；避免无意混用未类型化数组 |
| 测试在结束回合后读取已替换的意图数组 | 测试需在状态转换前保存本轮意图快照，并明确区分旧回合与新回合 |
| 先锋单位挡住神射手射线导致测试场景不成立 | 测试布阵前检查占格、视线、射程与意图优先级，确保测试只验证目标行为 |

## 每次修改后的即时检查

1. **改动范围**：确认只修改 qingxu443-dev/echo-game 的 `main`；不触碰拾光。
2. **类型检查**：检查新增变量、函数参数、返回值、信号、数组和 Dictionary 的类型声明。
3. **调用检查**：搜索所有被修改函数的调用点，核对参数数量、顺序、类型及默认值。
4. **资源检查**：核对 preload、load、场景脚本路径、节点路径和资源文件名。
5. **状态检查**：确认行动点、回合阶段、意图快照、取消/执行状态和胜负终态之间一致。
6. **测试检查**：为新机制增加正常、边界、失败和状态转换测试；确认测试没有依赖错误的站位或旧状态。
7. **静态复核**：重新读取 GitHub 上提交后的完整文件，不能只依据写入工具返回成功就认为修改正确。
8. **引擎验证**：有 Godot 运行环境时，立即运行项目导入/脚本解析及相关 headless 测试；出现错误先修复再继续开发。
9. **真实运行**：涉及场景、输入、绘制、动画或 UI 时，必须在 Godot 编辑器或设备运行确认，headless 测试不能替代。
10. **状态诚实**：分别记录“静态检查通过”“Godot 导入通过”“自动化测试通过”“设备测试通过”；没有执行的项目明确标记待验证。

## 错误处理流程

- 保存完整错误文本、脚本路径、行号和 Godot 版本。
- 先修复首个解析错误，再重新导入；一个解析错误可能遮蔽后续错误。
- 每次修复后重新运行导入/解析，不把多个未经验证的修复叠在一起。
- 再运行相关测试，检查测试是否真的覆盖修复行为。
- 最后运行主场景，检查交互、绘制与回合流程。
- 把新发现的错误模式补充到本清单，避免重复犯错。

## 当前验证能力边界

当前远程 GitHub 编辑环境没有可确认的 Godot 4.7.2 引擎执行能力。因此，远程开发阶段可做类型/调用/资源路径静态审查和测试用例编写；不能声称已完成 Godot 导入、解析或运行测试。每次向用户报告时必须明确这一差别。

- 鼠标技能按钮能施放守望壁垒与回响反击。
