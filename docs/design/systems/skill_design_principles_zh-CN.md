# ECHO 技能设计原则（Prototype 0.1）

本文确立技能设计评审标准。它是设计约束，不代表下列示例已经成为最终技能或已进入实现。

## 核心原则

技能的价值不能只由伤害倍率决定。每个技能至少应创造一种有意义的战术决策：站位变化、区域控制、行动时机、敌方意图干预、友军协同、资源交换或风险管理。

每个技能设计稿必须回答：
1. **战术用途**：它解决什么战场问题？与基础攻击有什么本质区别？
2. **使用窗口**：什么敌方预告、地形或站位使它特别有价值？
3. **反制空间**：敌人或玩家能如何应对？是否存在清晰预告？
4. **代价**：AP、冷却、站位风险、失去防御机会或其他代价是什么？
5. **协同关系**：是否与移动、守护、伙伴行动、标记或其他技能形成组合？
6. **失败情形**：目标离开区域、施法者被控制、目标死亡或路线被阻挡时如何处理？
7. **数值职责**：倍率只是技能效果的一部分；不能用高倍率掩盖缺乏机制的设计。

## 守誓者的职业表达

瑟弗林应围绕守护、承诺、反制和战场秩序形成独特身份。建议技能组形成互补，而非五个独立伤害按钮：

- **守护/阵地技能**：改变区域内友军承伤或敌方目标选择，鼓励主动站位。
- **标记/裁决技能**：对敌方行动施加条件；敌人选择执行或改变行动时，产生不同结果。
- **预备/反制技能**：针对已公开的敌方意图进行响应，奖励读懂敌方行动顺序。
- **位移/牵制技能**：改变单位位置、通路或攻击线，影响后续意图是否合法。
- **终结/兑现技能**：消耗前置标记、守护层数或反制成果，将此前布局转化为优势。

以上是机制方向。具体技能数量、名称、AP、倍率、范围和状态持续时间需在技能组整体评审后确定。

## 技能结构数据要求

每个技能应由数据描述，而不是在战斗控制器中散落硬编码：
- 稳定的技能 ID 与中文显示名称
- 技能类别与伤害类型（若造成伤害）
- AP 消耗
- 目标模式：单位、格子、区域、自身或路径
- 射程、范围形状与视线规则
- 攻击倍率（仅伤害技能需要）
- 状态效果、持续时间、叠加规则
- 是否改变、取消或追加敌方意图
- 预告文本/图形与执行效果
- 目标失效、施法者倒下、战斗结束等边界行为

## 设计验收标准

- 与基础攻击相比有清晰且可解释的独特价值。
- 至少存在一个有意义的使用时机或位置选择。
- 敌方意图相关效果必须能被玩家提前理解。
- 不允许预告内容与最终执行结果不一致。
- 状态、区域、标记和反制均有明确持续时间、移除条件及结算顺序。
- 不以堆叠倍率作为技能设计的替代品。
- 技能之间应有可读的组合关系，但不能要求玩家记忆隐蔽规则。

## 范围控制

Prototype 0.1 当前优先完成基础战斗闭环。技能机制先完成设计与数据结构，再按批准范围逐项实现；不借技能系统之名提前引入完整装备、天赋、局外成长或章节系统。

## 关卡与敌人遭遇设计原则（Prototype 0.1）

ECHO 的战斗变化应主要来自精心设计的关卡与敌人组合，而不是敌人行为或初始站位的隐蔽随机化。核心目标是让玩家能够观察、理解、预测并反制敌方行动，同时通过不同关卡获得新的战术问题。

### 固定性原则

- **敌人行为规则固定且可解释**：每种敌人拥有明确的行动条件、目标选择、攻击范围、追击规则与待机条件。相同战场状态应产生相同的决策结果；不使用玩家无法预判的随机判定改变关键行动。
- **关卡初始布阵固定**：每关明确配置敌人类型、数量、初始坐标、地形障碍与玩家初始位置。不得在基础原型中悄悄随机改变敌人站位。
- **敌方意图保持可读**：敌人的行动预告、执行顺序与最终结算必须遵循已公开规则；若执行时因目标移动、路线阻挡或目标失效而改变结果，应有明确规则和反馈。

### 关卡变化来源

关卡之间的差异优先来自以下可控设计变量：

1. 敌人类型与数量的组合，以及各类敌人的协作关系。
2. 敌人初始站位、朝向/攻击线（若系统采用）与彼此间距。
3. 地形、障碍、狭窄通道和可利用的战场空间。
4. 敌方行动优先级与意图组合形成的战术压力。
5. 关卡目标、特殊规则和阶段性事件（仅在项目范围批准后引入）。
6. 关卡排列与难度曲线：逐步从单一规则教学，过渡到多敌种协同、空间限制和多重意图应对。

### 难度设计要求

- 难度不能只依靠提高敌人生命值或攻击力。
- 优先增加战术决策的复杂度：目标优先级、站位取舍、路线管理、区域威胁与行动顺序。
- 新敌人或新规则应先通过可理解的情境教学，再与既有机制组合。
- 玩家失败后应能根据公开信息理解主要原因，并通过改变策略改善结果。
- 同一关卡在相同初始条件和相同玩家决策下，应尽可能得到一致的敌方行为结果，以支持学习、复盘与公平挑战。

### 随机性的边界

Prototype 0.1 以固定关卡配置和确定性敌人决策为基线，不把程序化随机布阵或随机敌人决策作为核心内容。未来若经单独设计评审引入随机变化，必须满足：变化范围受控、结果合法、信息透明、难度可控，并且不破坏玩家对敌方意图的判断。随机性不能替代关卡设计。

### 关卡配置验收标准

每个关卡配置至少应能明确回答：
- 玩家与所有敌人的初始坐标是什么？
- 敌人类型、属性和行动规则是什么？
- 地形障碍如何影响移动、视线和攻击？
- 首回合及后续回合可能出现哪些敌方意图？
- 关卡的主要战术考点是什么？
- 难度提升来自哪些可观察、可学习的因素？
- 相同条件下是否能稳定复现，便于测试与平衡？
