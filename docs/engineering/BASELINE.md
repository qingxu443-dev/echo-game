## 持续集成

`.github/workflows/suites.yml` 在每次推送到 `main` 和每个 PR 上复跑本文件的套件。

**断言数不写死在 workflow 里**：CI 从本文件的「断言总数」一行读取，因此基线仍只有一个维护点。脚本层面由 `EXPECTED_ASSERTIONS` 兜底——`tests/run_all.sh` 发现实际断言数低于声明值会直接退出 1。

这条守卫是必需的：某个套件走到不存在的调用会**中途报错但整体仍退出 0、failures=0**。

因此 `tests/run_all.sh` 现在还会直接拦截脚本错误：只要某个套件的输出里出现 `SCRIPT ERROR`，该套件记为 broken 并让整轮退 1，不再需要等断言数下降才发现。断言数守卫则继续拦住「少跑了几条但没错」的情况。

## 如何复现

```sh
# 全部套件 + 汇总
tests/run_all.sh                       # bash
tests\run_all.bat                      # Windows 双击或 cmd

# 单个套件
godot --headless --path . --script res://tests/test_core_rules.gd
```

每个套件结束会打印一行机器可读结果：

```
RESULT test_core_rules assertions=18 failures=0
```

`run_all` 汇总 `assertions` 与 `failures`，任一非零即返回非零退出码。
