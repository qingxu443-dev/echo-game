## 二、目标范围

Prototype 0.1 的目标内容：

- 一名可操作角色：守誓者瑟弗林（Sevrin）。
- 一个猎人通灵技：不占场的单次支援打击，两回合冷却（详见 P0）。
- 三种普通敌人：近战先锋、远程神射手、区域控制者。
- 一张完整战场，以固定关卡配置呈现。
- 瑟弗林的 V2 技能组：三项主动技能 + 一项被动；普通攻击已从玩家操作界面移除。
- 每个玩家回合 3 点行动点（AP）。
- 敌人行动预告与可见的行动顺序。
- 战斗胜利与失败判定，以及结束后的结算与重开流程。
- Android 横屏布局与触控操作。

## 四、待办任务（按优先级）

### P0｜猎人通灵（原「猎人同伴」）

**状态：已完成**——实现、自动化测试与无头运行均已通过；桌面人工操作确认并入 P1 一并检查。

**设计定位**：猎人不是常驻战场的单位，而是一个**通灵技**。施放后猎人出现在目标身旁、完成一次突袭后立即离场，不占用行动点，也不在战场上留下任何东西。

**规则**：

| 项目 | 规则 |
|---|---|
| 施放方式 | 技能栏第 4 项（数字键 4），选中后点击任意存活敌人 |
| 出现位置 | 目标周围第一个空闲正交邻格，顺序固定为上、右、下、左 |
| 存在时长 | 一击即走：结算完伤害即离场 |
| 代价 | **不消耗行动点** |
| 节流 | 两回合冷却（第 1 回合使用后，第 3 回合才可再次使用） |
| 不生成单位 | 不占格、不进入敌方行动顺序、不会被敌人锁定 |
| 失败条件 | 目标已阵亡 / 非敌人 / 四周无空位 |

**完成标准**：

- [x] 通灵技出现在技能栏并可通过数字键 4 选择
- [x] 施放后不消耗行动点
- [x] 两回合冷却正确计数与重置
- [x] 猎人不生成战场单位、不占格、不进入行动顺序
- [x] 目标四周无空位时施放失败，且不进入冷却
- [x] 被拒的施放不造成伤害、不重启冷却
- [x] 击杀最后一个敌人时正确触发胜利
- [x] 自动化测试通过（`tests/test_hunter_summon.gd`，39 条断言，Godot 4.7.2 headless）

**数值基线**（待实测调整）：攻击 1400、倍率 0.9，即原始伤害 1260；对近战先锋（防御 700）实际造成 741 点伤害。

### P3｜战斗结束后的流程

**状态：已完成**

目标：让一场战斗从开始、进行到结束形成清晰完整的体验。

已实现：
- 战斗结束时弹出结算面板，显示关卡、回合数、造成伤害、承受伤害、击败敌人数与剩余生命。
- 「重开本关」按钮可重置 AP、单位状态、护盾、终极能量、敌人预告与区域效果。
- 胜利时提供「下一关」；打完最后一关后按钮变为「从头开始」。
- 重开通过 `start_encounter` 重建全部战斗状态，不残留上一场数据。

完成标准：
- [x] 战斗结束有清晰的胜利/失败提示与统计展示
- [x] 提供重新开始当前战斗的入口
- [x] 重新开始时战斗状态完全重置

## 七、协作与提交要求

每项开发任务开始前，先确认目标分支、最新 Commit 和相关文件。

- 当前原型开发主线：`main`（默认分支，内容与可运行状态一致）。
- 新任务优先使用独立功能分支开发，再通过 Pull Request 合并。
- 不要直接把未审查的改动提交到 `main`。
- 每次改动说明修改文件、改动目的和影响范围。
- 源码变化后同步更新相关文档和测试。
- 提交时记录完整 Commit SHA。
- 测试包必须注明它对应的 Commit SHA。
- 分别记录静态检查、Godot 导入、自动化测试、桌面实测和设备实测；没有执行的项目标记为「待验证」。
- ECHO 与「拾光」项目严格隔离。
- 不擅自覆盖或替换朋友已经发布的测试包。

## 八、每项任务的状态定义

- **待开发**：功能尚未实现。
- **开发中**：正在修改或接入。
- **待验证**：代码看起来已具备，但还没有完成对应环境的实际测试。
- **已完成**：达到该任务的完成标准，并有相应验证记录。
- **暂缓**：明确不属于当前阶段，暂不安排。
